# Import Pipeline — Formats, Matching & Apply

Deep operational reference for the import system. Relocated from `AGENTS.md`.
Summaries: `docs/DOCUMENTATION.md` §11 (Import System).
NOTE: `docs/IMPORT_STRATEGY.md` and `docs/IMPORT_SYSTEM.md` are partially STALE (they predate external-ID-first matching and the ratings/emotions/comments/lists/character-vote imports) — this file is authoritative.
Read this file BEFORE touching anything under `apps/api/src/import/**`.

## Non-negotiable invariants

- Prefer authoritative external IDs over title matching; never override a live authoritative ID with a title guess.
- Preserve manual/local user data. Imports are additive or source-idempotent unless a documented rule explicitly says otherwise.
- Keep every apply path retry-safe and idempotent through stable source identities and section-level completion.
- Parse CSVs by headers only; tolerate reordered/extra columns and normalize `<nil>`/empty values to null.
- Never write wrong-type data to a media row; enforce type safety again at apply time.
- Never log comment text, secrets, or raw private archive content.

## TVTime GDPR CSV export

- TVTime GDPR export: `seen_episode_source.csv` + `tracking-prod-records.csv` (v1+v2) + `user_tv_show_data.csv` + `followed_tv_show.csv` + `lists-prod-lists.csv`.
- v2 per-episode rows → WATCHED_EPISODE. v2 summary rows → WATCHLIST_SHOW.
- v2 rewatch tally: `watch-episode-<series>-<user>` summary rows carry `rewatch_count`; `rewatch-episode-<series>-<user>-<N>` event rows carry ordinal N. Each signal is incomplete alone (event ordinals can exceed `rewatch_count`; summaries can lack it), so each row reports `watchCount = max(1, rewatch_count+1, N+1)` and the max-dedupe keeps the highest — never summed (v1/v2 overlap would double-count). v1 `rewatch`/`rewatch_count` typed rows carry no series name/id (series_uuid only) and duplicate `rewatched_episode.csv`'s `cpt` tally — ignored by design.

### Lists & favorites

- Lists + favorites: `lists-prod-lists.csv` has three row kinds — metadata (`collection`/`count`), favorites pseudo-lists (`s_key` = `favorite-series`/`favorite-movies` → NOT lists: staged as FAVORITE_SHOW/FAVORITE_MOVIE items, applied by the shared favorites pipeline, deduped by mediaId), and real custom lists (`s_key` = uuid → `CustomList` with `source=TVTIME`, identity by `(userId, source, sourceKey)`). Unnamed list rows recover their title from the `collection` row's `lists` blob (a Go-map dump mapping s_key→name; `parseGoMaps` in `lib/list-objects.ts`). Series objects carry a TVDB `id` → matched through the id-authority gate (title search only when a name exists in the `{tv_show_id→name}` map — never title-match a placeholder). Movie objects carry ONLY a `uuid` → resolved via `buildMovieUuidNameMap` (uuid→name recovered from v1 tracking / ratings-live / emotions-live rows and movie-comment `entity_uuid` rows). No-identity objects (unknown uuid, dead id without name) are counted in the list's `unresolvedCount`, NEVER staged (a title-less row is unreviewable noise). Visibility defaults PRIVATE. Re-import updates metadata + adds missing items; manual lists untouched. Legacy cleanup: pre-fix imports created CustomLists with sourceKey `favorite-series`/`favorite-movies` — every TVTIME confirm runs `migrateFavoritePseudoLists` (items → real Favorite rows deduped by mediaId, then the pseudo-lists are deleted; idempotent). See `lib/list-objects.ts` + `lib/lists.ts`.

### Ratings

- Ratings: episode/movie vote files (`ratings-*-votes`) use the verified `stars_wording_scalev2` set (id→star via final `vote_key` segment; UUID movie keys split on last `-` only). `tv_show_rate.csv` → direct 1–5 show rating (out-of-range skipped). Unknown ids/sets skipped with warnings, never guessed. Conflict policy: never overwrite manual/local ratings; idempotent via `source=TVTIME`+`sourceKey`. See `lib/ratings.ts`. NOTE: `tv_show_rate.csv` is also explicitly in `SKIP_PATTERNS` (`"rate"` ≠ `"rating"`) — without it the main watched-content pipeline misclassifies the file as `generic_movie_watched` and fabricates WATCHED_MOVIE items (the Sense8 regression). Cross-type safety is layered on top: `matchByTvdbId` refuses matches whose resolved media type ≠ item type, and `applyBatch` runs a batched type guard (wrong-type items dropped + logged). Existing wrong-type rows (`user_movie_status` / `watch_history(MOVIE)` on SHOW rows) are purged by the type-mismatch repair (Metadata Health `movieDataOnShows` stat).

### Emotions

- Emotions: `emotions-*-votes` use the verified `12_all` set (id 36 → enum `UNDERSTANDING`). Legacy `episode_emotion.csv` ids (1,3,6,7,…) are unsupported. Multiple emotions per target retained; additive apply (never removes existing); `tv_show_user_emotion_count.csv` is an aggregate, skipped. See `lib/emotions.ts`.

### Character votes

- Character votes: `show_character_episode_vote.csv` normally stages `EPISODE_CHARACTER_VOTE`; when the archive has already proven that the source episode is a single movie or a coordinate in a numbered movie group, it stages `MOVIE_CHARACTER_VOTE` against that exact TMDB-canonical movie. Historical character choices are collapsed to the latest row per source episode. Episode targets resolve through the standard TVDB-alias/S/E chain. Character resolution during confirmation is fully local: title-scoped `media_cast_external_ids` aliases first, then the legacy `media_cast.characterExternalId`, with zero provider calls per vote and no overwrite of existing/manual votes. Missing show roles queue one `CAST_ONLY` series refresh; missing movie roles queue one bounded movie cast-enrichment job. Movie enrichment may add a role alias or protected supplemental cast row only when TVDB character/person evidence and a TVDB-movie remote TMDB id prove the role belongs to the canonical movie; it never replaces TMDB metadata, cast ordering, recommendations, or watch providers. Provider failures remain pending. Successful authoritative refresh emits `metadata.cast-refreshed`, which replays completed imports and terminally skips only roles still absent. Stale episode FKs are repaired locally before insert, imported timestamps are preserved, and repeated imports remain idempotent. Manual resolution to a movie retypes an episode character vote to `MOVIE_CHARACTER_VOTE`.

### Comments (full-thread, shadow users)

- Comments: FULL-THREAD import (`comments-prod-comments.csv` + legacy `episode_comment.csv` + `show_comment.csv`) — owner-authored AND third-party comments, top-level AND replies. Owner resolved from `user.csv`/`user_personal_data.csv` (unresolvable → whole file skipped, safe). Likes, reports, read markers, translations, profile-wall comments still skipped+counted. Embedded `replies` blobs are IMPORTED (`parseEmbeddedReplies` in `lib/comments.ts`) — real exports carry third-party authors ONLY inside these blobs (never as CSV rows), so this is what actually produces shadow users. The Go `%v` map dump is parsed known-key-aware (sorted keys; values with spaces end at the next known key — the generic space-terminated `parseGoMaps` can't be used); float user ids (`2.1270298e+07`) convert to exact integer strings; missing/`0` user ids map to ONE shared deleted-user shadow (external id `'0'`); nested `replies` lists recurse with depth+1; blob replies inherit the parent row's target and link via the parent's `uuid`. Third-party authors get deterministic SHADOW accounts (`users.isShadow`, email `shadow+<source>-<externalId>@shadow.local`, stable generated username from `lib/shadow-user.ts`) — shared across imports, so the same author imported from two archives is one identity; comment dedupe is GLOBAL by (source, sourceKey) — a source uuid identifies one comment worldwide, so a blob-reply copy is never duplicated under a shadow when the real author (or another archive) already imported it. SHADOW CLAIMING: the archive owner's TV Time id is persisted on `Import.ownerExternalId` at staging; on confirm, `claimShadowAccount` checks for a shadow with that external id — its comments are reassigned to the real user (colliding duplicates re-point their children to the real comment, then are dropped) and the shadow user is deleted (TVTIME only). Legacy files without `user_id` attribute to the owner. Replies keep their parent link: the v2 reply row's `parent_uuid` is a SELF-reference (the row's own uuid — the real parent lives in the sort_key, `reply-<own>-<epoch>-<parent>`, extracted at normalize; self-references without a sort_key parent are treated as parentless); parent resolved in-batch (topological passes) or from the DB by (source, sourceKey); a reply whose parent is missing stores `parentSourceKey` (the parent's staged sourceKey, `tvtime|<uuid>`) and is linked later by `reconcileCommentParents` — which runs after every comments apply, so a parent imported later (even by a DIFFERENT user) completes threads retroactively; pass-loop leftovers (in-batch parent failed a guard) import as strays too — only a TRUE self-cycle (parent key == own key) is skipped. Episode → episode thread; show-page (`show_comment.csv`, v2 `entity_type=series/show`) → show thread; movie → movie thread. Visual attachments from the `image` column: **GIFs** stored by URL (`comment.gifUrl`); **static images** (png/jpg) downloaded + fed through the `CommentImage` pipeline (`CommentImageService.attachFromBuffer` → resize/encrypt/store/moderate), same as user-uploaded pictures; image-only comments are imported too. Created directly via Prisma (no `comment.created` event → no badges, no notifications); historical timestamps preserved; `source=TVTIME`+`sourceKey` for idempotent re-import. Dedupe is multi-key: a candidate merges with an earlier one if ANY collide — source identity (uuid / legacy `id`), the canonical numeric comment id (v2 `comment_id` column, rare legacy-era backfill, or any bare-numeric source id), or a content fingerprint (target + text-hash + created MINUTE). Duplicate rows are field-merged rather than one row winning wholesale: the v2 UUID/image/language/reply metadata is combined with the legacy row's TVDB episode id, show title, and S/E coordinate. Covers the same comment exported twice across files with different id spaces without discarding the only matchable target identity. `is_spoiler`/`spoiler_count` map to `Comment.isSpoiler`/`Comment.spoilerCount` (isSpoiler = flag OR count ≥ 5). Comment text is NEVER logged. See `lib/comments.ts`.

## CSV compatibility rules

- CSV compatibility: header-based mapping only (never positional); `<nil>`/empty → null; reordered/extra columns tolerated; unknown files skipped. Numeric TVDB series and episode IDs serialized by spreadsheet tooling as floats or safe scientific notation (for example `451834.0` or `4.51834e5`) are canonicalized to positive integer strings before matching. Fractional and unsafe numeric values are not guessed: they remain untrusted identity signals so the authority gate blocks unsafe title fallback.
- Profile detection matches on the entry BASENAME only (`detectProfile`) — zips created from a folder prefix every entry (e.g. `gdpr-data/…`), and a prefix containing a skip-list word must never classify the whole archive as unknown.
- Artwork-only TV Time tables (`users-customization-prod-data.csv` and `user_custom_show_image.csv`) are unsupported: poster/fanart timestamps are not viewing activity. Generic movie-history detection requires a movie filename/column signal plus an explicit viewing timestamp such as `watched_at` or `watch_date`; title or payload text containing the word `movie` never changes a row's media type. `created_at` and `updated_at` alone never create watch history. Movie-shaped rows never promote `s_id`, `series_id`, or `tv_show_id` into a movie external ID because those columns belong to TVDB's independent SERIES namespace.

## Trakt GDPR export (JSON zip)

- Trakt GDPR export (JSON zip): detected by `isTraktArchive(zip entry names)` in `lib/trakt/detect.ts` BEFORE CSV inference (a standalone `.json` upload with a Trakt filename also routes there). Processed: `watched-history-*.json` (authoritative per-play history, episodes+movies — collapsed per item: `watchCount` = plays, `watchedAt` = earliest play, one `watchHistory` row), `ratings-{shows,episodes,movies}.json` (Trakt 1–10 → `clamp(round(r/2),1,5)`), `lists-watchlist.json`, `lists-favorites.json` (→ FAVORITE_SHOW/MOVIE), `lists-lists.json`, `comments-{episodes,movies,shows}.json` (top-level only, `parent_id` skipped, reviews imported as comments), `user-settings.json` (`browsing.locale` → archive language for title fallback). `watched-movies/shows-*.json` are aggregates — used ONLY when no history files exist (movies via plays/last_watched_at; aggregate-only shows skipped, never fabricate episode rows); superseded when history exists. Everything else (`collection-*`, `hidden-*`, `likes-*`, `network-*`, `notes-*`, `user-*`, `watched-playback`, `ratings-seasons`, `comments-{seasons,lists}`) unsupported+counted. See `lib/trakt/*`.
- Trakt matching is external-ID-first (`matcher.matchByExternalIds`): TMDB id (local `ExternalId` → light upsert by id; shows skip the heavy `getShow`) → IMDB id (entity-kind-scoped local mapping → exact `/find` recovery) → TVDB id (same authority gate as CSV's `rawTvdbSeriesId`) → title fallback. IMDB deliberately precedes TVDB because some TV Time movie rows carry a valid movie IMDB id alongside an unrelated TVDB SERIES id; recovered IMDB ids are attached immediately to the matched media. Episodes: `resolveEpisodeByExternalIds` (EpisodeExternalId, TMDB then TVDB) → S/E fallback. `Import.format` (`'tvtime'|'trakt'`) is persisted during processing; the apply stage tags Rating/Reaction/Comment/CustomList records `source=TRAKT` (parameterized, never hardcoded) so both imports stay idempotent independently.

## TV Time JSON GDPR export

- TV Time JSON GDPR export (JSON zip + flattened CSV duplicates): detected by `isTvTimeJsonArchive(zip entry names)` in `lib/tvtime-json/detect.ts` AFTER the Trakt check, BEFORE CSV inference (markers: `shows.json` / `movies.json` / `activity_history.csv` basenames; standalone `shows.json` etc. uploads also route there). Processed: `shows.json` (watched episodes + structural footprint; `imdb:"-1"` sentinel → null), `movies.json` (`is_watched=true` → watched, `false` → WATCHLIST_MOVIE), `favorites.json` (→ FAVORITE_SHOW/MOVIE via `added_at`), `lists.json` (→ CustomList; `is_public` respected — PUBLIC when true; `sourceKey = tvtime:list:<normName>`). Ratings are the nullable 1–10 `rating` field inside those files → `clamp(round(r/2),1,5)`; episode ratings deduped by TVDB episode id across ALL files (a rating can exist only in favorites/lists embedded seasons); `voteKey=null` → stable `episode:<id>`/`media:<id>` apply identity. **`activity_history.csv` is parsed ONLY for its show `is_watchlisted` flag** (→ WATCHLIST_SHOW) — that signal exists nowhere in the JSON and shows.json `status` can't reproduce it; every other CSV (`favorites.csv`, `list_*.csv`, …) is a flattened duplicate → unsupported+counted. `special:true` episodes (embedded in REGULAR season numbers, sharing S/E keys with regular episodes) resolve ONLY via the TVDB episode external-id path — never S/E-matched (would corrupt into regular episodes); unresolved specials are skipped+counted. `Import.format` stays `'tvtime'` so records tag `source=TVTIME` and share the conflict domain with legacy CSV imports. Show `status` (up_to_date/continuing/…) is NOT imported. See `lib/tvtime-json/*`.

## TV Time Out export (browser extension)

- TV Time Out export (browser-extension JSON zip, NOT the official GDPR export): detected by `isTvTimeOutArchive(zip entry names)` in `lib/tvtime-out/detect.ts` AFTER the Trakt + tvtime-json checks, BEFORE CSV inference (markers: dated `tvtime-(series|movies|failed|summary)-*` basenames; standalone series/movies JSON uploads also route there). Processed: `tvtime-series-*.json` (watched episodes + structural footprint + watchlist + favorites) and `tvtime-movies-*.json` (watched movies / watchlist / favorites). Every show/episode/movie carries a TVDB id (imdb always null on shows/episodes). `watchCount = max(1, watched_count, rewatch_count + 1)` for episodes, `rewatch_count + 1` for movies. **Fully-unwatched shows → WATCHLIST_SHOW** (listedAt = `created_at`); `is_favorite` → FAVORITE_SHOW/MOVIE independent of watched state. Specials (`special:true` episodes embedded in REGULAR seasons, plus `is_specials:true` seasons) resolve ONLY via the TVDB episode external-id path — never S/E-matched; unresolved specials skipped+counted; footprints exclude specials. `tvtime-failed-*.json` (shows the extension couldn't export) is parsed for a WARN log only, never staged; `tvtime-summary-*.html` is unsupported+counted. No ratings/emotions/comments/character votes/lists exist in this format. Show `status` is NOT imported. `Import.format` stays `'tvtime'` (same underlying TV Time account) so records tag `source=TVTIME` and dedupe against GDPR CSV + tvtime-json imports of the same account. See `lib/tvtime-out/*`.

## External-id matching (all imports)

- External-id matching (all imports) uses TMDB → entity-kind-scoped IMDb → TVDB → validated title/year. IMDb precedes TVDB so a valid movie IMDb ID cannot be overridden by an unrelated TVDB series ID. Existing local aliases are unique + entity-kind scoped and are trusted immediately when the target is populated. An episode-bearing import that points to an empty local show revalidates that TVDB identity once, preventing a stale provider-merge remnant from making every episode reviewable. Historical wrong-kind/suspect aliases are handled by Metadata Health's audited external-id/duplicate repairs, not inline. On a genuine local miss, show TVDB IDs resolve through exact TMDB `/find`; TVDB **movie** IDs never use that endpoint because TMDB does not expose a TVDB-movie namespace. They resolve through TVDB `/movies/{id}/extended` remote TMDB/IMDb IDs, with IMDb translated through TMDB `/find`. Every new result must match the expected entity kind before its identifier is attached. If every authoritative ID is confirmed dead, recovery may use an exact provider title/year result; it never accepts the provider's first fuzzy suggestion while that source identity is unresolved. For shows, a lightweight TMDB routing profile normally applies the strict Animation+`anime` rule before hydration: anime uses the verified TMDB→TVDB series ID, general shows use TMDB, and TVDB-only shows remain locked fallbacks. A narrow TV Time replacement-ID exception does not require TMDB `/find`: after every exported SERIES id is proven dead and exact local catalog matching has missed, a watched-show footprint may route directly to TVDB only when TVDB search yields exactly one SERIES whose title/alias, optional year, complete regular-season **range**, and TVDB `Anime` genre all agree. Every candidate season must appear in the archive and contain at least the highest watched episode; additional unwatched episodes are allowed for an exact title/alias. A longer legacy prefix match remains weaker evidence and therefore requires exact episode counts. A pre-colon legacy title is tried as one bounded second search when needed. It receives an explicit `ANIME_TVDB` decision and is fully hydrated from TVDB before episode resolution; ambiguity or provider failure remains unresolved. Conflicting source IDs remain only in raw import diagnostics.
- TVDB SERIES and MOVIE identifiers are separate numeric namespaces and may reuse the same number for unrelated titles. A same-number movie response is therefore a namespace-collision diagnostic, not identity evidence; it is accepted only when title/year and a real TMDB movie cross-id independently verify the imported identity. After every exported series ID is confirmed stale and normal show recovery fails, a watchlist-only or single-S1E1 footprint may search movies by exact title/original title/TVDB alias. Numbered film groups map each source S/E coordinate independently. Once either movie decision is proven, compatible watched/watchlist/favorite/rating/emotion/comment/character-vote rows become movie rows. Ambiguous media stays reviewable. This changes the staged import target, never an existing catalog row's media type.
- A separate local-only rule handles a dead TVDB synthetic show that represents a numbered film cycle. It requires at least two contiguous imported coordinates starting at one, in either `S1E1..N` or `S1..NE1` form, and exactly one hydrated TMDB movie for every matching `Case N`/`Part N`/`Film N`/`Movie N` title. Each source episode becomes the corresponding watched movie (for example _Psycho-Pass: Sinners of the System_ Case.1–3 and _Kizumonogatari_ Part 1–3). Missing or duplicate ordinals, a non-contiguous source footprint, or a live/inconclusive authoritative series id leaves the rows unresolved; the rule never collapses the group into one movie and makes no provider calls.
- Unnumbered `is_unitary=true` film groups use a second fail-closed path after the archive's standalone movies have been matched. The group must contain at least two contiguous coordinates on one axis and exactly the same number of uniquely matched archive movies sharing the group title prefix; every movie must have a TMDB identity and an unambiguous release order. This resolves subtitle-based cycles such as _Harry Potter_ without a provider call. If the archive has no member-movie rows, only an explicitly named `... Movies`/`... Films` group may fetch its TVDB episode structure once and map every coordinate to one exact, already-hydrated local movie title. One deleted-provider exception is pinned by all of its historical evidence: TVDB series `352423`, exact title `Dragon Ball Movies`, and the complete `S1E1..E13` footprint map to the original 13 Dragon Ball Z theatrical films by exact TMDB id; incomplete or conflicting local identities fail closed. Generic unitary series, partial sets, duplicate dates/titles, provider failures, and ambiguous matches remain unresolved.
- Known TV Time catalogue artifacts are reconciled before matching. The exact `WILL BE DELETED)` placeholder and any dependent interaction rows are counted as ignored duplicates. A complete, TVDB-`349062` 22-part _Arrested Development: Fateful Consequences_ footprint proves canonical _Arrested Development_ season 4 complete (TVDB `72173`, 15 original episodes); existing canonical rows win. Because the recut is a many-to-many edit, its episode ratings, emotions, comments, and character votes are suppressed as alternate-cut duplicates rather than guessed onto unrelated original episodes. Partial or identity-unverified recuts remain reviewable.
- Replacement searches verify the bounded provider candidates again against hydrated translations and TMDB alternative titles; the search result's display title is not assumed to contain every legacy/romanized alias. This recovers dedicated anime records such as _Hanamonogatari_ and _Nekomonogatari (Kuro)_ while the complete-season guard still rejects the broad _Monogatari_ parent. A dead TVDB anime identity ending explicitly in `OVA(S)`/`Special(s)` may collapse to exactly one TVDB Anime series whose title/translation equals the suffix-free base. Deleted one-off show identities may use a tiny documented TV Time alias/synonym plan only inside the existing show→movie gate (including the anime-only _I Love My Younger Sister_ OVA and TV Time's `Revival` → provider `Re;surrection` wording); uniqueness, year when present, anime evidence when required, and a real TMDB movie identity are still mandatory.
- Once a film group is fully recovered from watched episodes, a same-identity synthetic `WATCHLIST_SHOW` row is counted as a duplicate instead of remaining as an impossible group-level review item. It does not create watchlist state on already-watched member films. A direct movie watch already present elsewhere in the archive wins over its synthetic episode duplicate (watch count and latest timestamp are preserved), preventing duplicate movie-history rows. The coordinate mapping is shared under both provider and title identities so episode ratings, emotions, comments, and character votes are retyped against the same exact movie.
- Before row staging, each format bulk-loads all available media and episode external IDs, then active S/E coordinates for matched shows (chunks of 5000). Distinct genuine misses run through a bounded worker pool (`IMPORT_MATCH_CONCURRENCY`, default 8); ratings, emotions, comments, and character-vote resolution use the same pool. A provider episode recovery promise (including a failed/deleted-id result) is shared by external episode ID across the complete archive, so duplicate rows and secondary files never repeat the network wait. Provider rate limiters remain authoritative. Classification enrichment is queued once per distinct media per import.
- TV Time CSV watched episodes bulk-resolve their TVDB episode IDs globally **before deduplication or title matching**. Rows are partitioned by exact local episode owner, then a direct or single unambiguous archive-wide TVDB series ID, with title/year used only when neither exists. This lets a title-only duplicate from a secondary file join the same series-backed row while keeping ambiguous same-title remakes separate. Within each partition, the exact episode owner is authoritative and wins over coarser series-ID/title evidence. Only aliases spanning multiple local parent shows inside the same authoritative partition are considered an identity conflict; those remain reviewable and title fallback is refused. This lookup also primes the scoped episode cache, so the later episode pass does not repeat the database work.
- Local exact-title matching always loads the candidate set; it never uses unordered `findFirst()`. An explicit source year must be within one year, and a watched-show candidate must contain every imported season/episode coordinate in the archive footprint. An incompatible single candidate is rejected just like an incompatible duplicate, preventing a same-title show with coincidental S1 coordinates from being staged as matched.
- TV Time CSV imports build a per-archive identity index before matching. `Title (YEAR)` and the normalized `Title`+year form share one year-aware fallback key; TVDB series IDs are collected directly from every parsed row, including rows that do not stage an import item. Positive S/E coordinates are reused across every file carrying the same TVDB episode ID (`The Woods` is a real export regression). Deleted aliases exported as `E0` can reuse an archive-only sequence relationship only when the target episode already has independent positive evidence for the same show/season: an exactly bounded sequence hole, an immediately adjacent obsolete alias, or complete obsolete-id and positive-coordinate sets that have identical cardinality and prove a contiguous E1..EN season. Watch timestamps/order never infer an episode. Proven coordinates are applied before watched-row deduplication, so replacement aliases merge without collapsing distinct `E0` episodes. TV Time's archive-scoped movie UUID is also collected across tracking/watchlist (`uuid`), ratings/emotions (`uuid`), movie comments (`entity_uuid`), and list objects; release-date evidence on one row is reused by every row for that UUID. UUID-bearing movie rows with a valid release date may also provide `alpha_range_key`: its `follow`/`watch`/`towatch` title slug becomes the preferred canonical candidate (for example localized `Torden` → `Mortal`), while the exported title remains a secondary alias. Later episode ratings, emotions, comments, and character votes resolve their own TVDB episode alias first, while movie extras reuse the already-verified movie UUID binding. Conflicting years, titles, UUID bindings, or episode owners are never guessed: ambiguous evidence falls back to the normal review-safe matcher.

## Structural guard

- **Structural guard** (`needsTvdbRehydration`) is diagnostic only. A footprint mismatch never authorizes non-owner hydration. For a TMDB-owned show, unresolved TVDB episode ids are bulk-translated through Structure Remap's conservative matching ladder using one complete TVDB **official/aired-order** routing snapshot per show. TV Time archives carry those official episode identities even when the series later selects a different TVDB default order. If any imported alias for a show is missing, every alias for that show is revalidated in the same snapshot; fully resolved shows keep the indexed database fast path. This prevents an older coordinate-attached alias from bypassing the bridge without adding one provider request per episode. The read-only bridge does not activate foreign rows, move aliases, switch authority, or change the Dual Season Structures metric. `ANIME_TVDB` and other TVDB-owned shows bypass it. Once that complete snapshot verifies an identity but cannot place it, the importer must not fall through to the source TVDB S/E coordinate against TMDB; the row remains reviewable until Metadata Health can reconcile the structures. Provider failure remains reviewable and suppresses a per-episode TVDB retry fan-out; Metadata Health remains the only repair/write surface. The matching progress range reports the alias-snapshot and episode-resolution phases independently so large provider reconciliations do not leave the client parked at 40%.

## Episode resolution chain

- Episode resolution chain: canonical active `episode_external_ids` → batched TVDB-alias-to-canonical bridge for TMDB-owned shows → exact S/E for regular episodes → TMDB `/find` recovery with the TVDB episode ID → direct TVDB episode lookup when `/find` misses and the batch snapshot did not already evaluate that identity. Once the complete official-order snapshot verifies an id but cannot place it inside the matched TMDB show, the generic CSV path does not repeat TMDB `/find` for every row unless the source season exceeds the matched show's entire canonical season range. That bounded exception preserves cross-show anthology routing without reintroducing provider fan-out on incomplete daily-show structures. The episode-level identity may override the source series-level target: TVDB anthology seasons grouped under one series can route to separate TMDB shows (for example `The Haunting` S1 → _The Haunting of Hill House_, S2 → _The Haunting of Bly Manor_; Netflix `Monster` seasons route the same way). The exact TMDB `/find` episode result light-upserts/hydrates its own parent show, resolves TMDB's S/E, attaches the TVDB episode alias there, and is cached once for every archive row carrying that episode id. Direct TVDB recovery requires the episode's parent series ID to equal the matched media's exact TVDB series alias; regular episodes may reuse that verified provider S/E coordinate. A same-day canonical episode that already owns a different TVDB alias may only be reused when source/target runtime proves a split-part → combined-broadcast relationship; distinct same-day episodes remain reviewable. When the local show uses a different provider numbering scheme, an exact provider episode title on the same air date may identify the single local episode. Specials remain exact-alias-only. A matched TVDB show with zero active episodes is force-refreshed once through the metadata service even when its light metadata row is fresh. Missing shows try a bounded first/middle/last spread of their imported TVDB episode IDs so one stale alias cannot block a live sibling. A deleted provider id exported without a usable episode number remains a terminal `UNMATCHED` diagnostic rather than a misleading `SxE0` review item; legacy-unmapped episodes are never import targets. The comment pipeline is the one preservation exception: when an episode reply has an identified show but TV Time exported a dead `SxE0` placeholder, it becomes a matched show comment and retains `sourceTargetType=episode` plus the original season/episode/external-id diagnostics. It is never attached to a guessed episode.

## Title normalization (Unicode-aware)

- Title normalization (`normTitle`) is **Unicode-aware** — it keeps letters/numbers from EVERY script (Korean, Japanese, Arabic, Cyrillic…), so distinct non-Latin titles NEVER collide. An ASCII-only class normalizes them all to `''`, which once let a bulk by-title resolve match dozens of unrelated Korean/Japanese items to one show (the Yatterman incident). Provider matching accepts an exact normalized localized title **or** TMDB's `original_name`/`original_title`; a movie exported as `Projām` can therefore match TMDB's localized `Away` result confidently instead of being downgraded to a first-result 50% guess. Bulk title paths (`resolveAllForShow`) also refuse an empty normalized identity outright. PostgreSQL stores an indexed normalized base title and projects localized `MediaItem.titles` entries into `media_title_aliases` through a trigger; imports no longer scan `media_items` with `jsonb_each_text`.

## Anime routing evidence

- Normally, only a TMDB routing profile containing both genre id 16 (`Animation`) and the `anime` keyword can route a show to TVDB structure. Kitsu/Jikan matches, Japanese origin/language, Animation alone, and the keyword alone remain enrichment or review evidence only. The sole import exception is the guarded dead-TVDB-series replacement flow described above: a unique, structurally verified TVDB SERIES carrying TVDB's explicit `Anime` genre may receive `ANIME_TVDB` authority without TMDB `/find`. This exception resolves provider structure only; it does not loosen general catalog classification, title matching, or cross-provider merging.

## Batched apply

- Review UI item queries use a single stable page of up to 500 rows (the API cap matches the mobile request), because offset pages drift while manual resolutions move rows between statuses. Mobile shows the persisted `UNMATCHED` total and provides a dedicated filter so a zero `NEEDS_REVIEW` count cannot hide unresolved diagnostics; confirmation still skips those rows unless the user resolves them. Import-item queries bypass the app-wide five-minute stale window and always refetch on mount/filter return; a transient request failure is shown as retryable instead of masquerading as an empty filtered view.
- Manual episode resolution uses the same `resolveAllForShow` pipeline in mobile and admin. A selected show may apply to only the item, the item's source season, or every unresolved row with the exact normalized source-show title. Season scoping preserves anthology mappings; movie targets always remain one-item resolutions. Admin calls are owner-scoped and audited.
- When processing reaches `READY_FOR_REVIEW`, the user receives a deduplicated SYSTEM notification with a deep link to that import. Delivery is best-effort and follows notification preferences and the push feature flag; notification failure never changes a successful import into a failed one.
- Batched apply: bulk `IN` reads and `updateMany` writes are capped at 5000 IDs per statement; `createMany` chunks are additionally reduced by row width to stay below PostgreSQL's 32,767 bind-variable limit. Apply uses **one raised-timeout `$transaction` per section** (episodes/movies/watchlist/favorites/lists), not one giant transaction — each section marks its items `APPLIED` so BullMQ/manual retries are idempotent. Apply timeouts via `IMPORT_TX_TIMEOUT_MS` (default 60s).
- Every episode-scoped match (watched history, rating, emotion, comment, and character vote) is revalidated in one local batched preflight immediately before apply. If metadata replacement removed a staged episode row, an explicit TVDB episode identity must resolve through its active alias inside the already-matched show; it never falls through to a potentially incompatible TMDB coordinate. Older staged rows without an external identity may use one unambiguous positive regular-season S/E replacement inside that show. Specials never use S/E fallback. Irrecoverable stale rows become `SKIPPED` instead of aborting confirmation, so an old `FAILED` import can be confirmed again while already-`APPLIED` sections remain untouched and all other valid activities complete.
- `<nil>` values are normalized to null (not 0).
- After import confirm: `rebuildShowStatuses` recalculates watched/total counts.
- Configurable worker concurrency via `IMPORT_WORKER_CONCURRENCY` env.
- Configurable bounded provider-miss concurrency via `IMPORT_MATCH_CONCURRENCY` env (default 8).
